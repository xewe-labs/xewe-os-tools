xewe-os-tools 3.1.3

xewe-os-tools is the Python package behind every XeWe OS firmware project (`xewe`: setup, build,
flash, serial, provision, test, release, release-card, format, brand-lint) and the reusable GitHub
workflows the other repos call. 3.1.3 follows 3.1.2 and makes the project's Config.h a catalogue:
every generated line is commented out until the user uncomments it.

CHANGED SINCE 3.1.2

- `xewe modules generate` copies each module's and the core's Config.h block into the project's
  Config.h as a catalogue of commented-out overrides: every entry keeps its comment line and its
  definition is commented out with `// ` (the `#ifndef` guard and the `NAME_PROMPT` line are
  dropped; a chip-conditional entry keeps its `#if`, `#else` and `#endif` lines, each prefixed).
  Nothing in a generated block is active, so the module fallbacks supply every value until a line
  is uncommented, and an uncommented line is a bare `#define` (XeWeOverrides.h is read after it).
  The block header reads "Values of the <slug> module. Uncomment a line to override; keep both
  markers." A module Config.h without section markers is still copied verbatim, with its old
  header.

BREAKING

- A project generated by 3.1.1 or 3.1.2 keeps its old blocks, because a block is never rewritten.
  Delete the blocks you want in catalogue form from the project's Config.h and run
  `xewe modules generate` again.

INSTALL

- Projects: `[tools] ref = "3.1.3"` in xewe.toml, then `./setup.sh`.
- Workflow callers: `uses: xewe-labs/xewe-os-tools/.github/workflows/<workflow>.yml@3.1.3`.

TESTING

What was tested, on which tree and with which result: release_card.md, generated by
scripts/release.sh --prepare 3.1.3 and attached to this release.
