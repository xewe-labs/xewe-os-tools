xewe-os-tools 3.1.4

xewe-os-tools is the Python package behind every XeWe OS firmware project (`xewe`: setup, build,
flash, serial, provision, test, release, release-card, format, brand-lint) and the reusable GitHub
workflows the other repos call. 3.1.4 follows 3.1.3 and writes the project's Config.h catalogue in
the block-comment form: text in `/* */`, commented-out code in `//`.

CHANGED SINCE 3.1.3

- `xewe modules generate` writes the catalogue blocks of the project's Config.h with the markers
  `/* ---- <slug> (xewe modules generate) ---- */` and `/* ---- end <slug> ---- */`; each section
  marker and each entry's comment line is a `/* ... */` line, and only the commented-out definitions
  use `//`. The block header reads "Values of the <slug> module. Uncomment a line to override; keep
  both markers."
- Section markers are recognised by the pattern `/* ---- <text> ---- */`, and by the `//` form of a
  Config.h not yet converted; any number of sections, in the order found. A `//` comment line of an
  unconverted source is converted; a comment line longer than 100 columns is split, so
  `xewe format --check` reports nothing on a freshly generated Config.h.
- Projects generated by 3.1.1 to 3.1.3 keep their blocks: both marker forms are detected, no block
  is added twice or rewritten.
- A Config.h without section markers is still copied verbatim.
- doc/spec.md section 10 and the modules README describe the form.

BREAKING

- None. A project that wants the new form deletes its old blocks and runs
  `xewe modules generate` again.

INSTALL

- Projects: `[tools] ref = "3.1.4"` in xewe.toml, then `./setup.sh`.
- Workflow callers: `uses: xewe-labs/xewe-os-tools/.github/workflows/<workflow>.yml@3.1.4`.

TESTING

What was tested, on which tree and with which result: release_card.md, generated by
scripts/release.sh --prepare 3.1.4 and attached to this release.
