xewe-os-tools 3.1.1

xewe-os-tools is the Python package behind every XeWe OS firmware project (`xewe`: setup, build,
flash, serial, provision, test, release, release-card, format, brand-lint) and the reusable GitHub
workflows the other repos call. 3.1.1 follows 3.1.0 and is the tools side of the configuration
scheme described in doc/config.md of xewe-os-core: build information first, overrides last, values
from the dotenv file through Config.h, and first-boot values in the project's Config.h.

CHANGED SINCE 3.1.0

- Every C++ translation unit starts with three headers, in this order: XeWeBuildInfo.h
  (BUILD_VERSION, BUILD_TIMESTAMP, BUILD_CHIP, XEWE_CHIP_<chip>), the project's Config.h as
  arduino-cli copies it into the build path, then XeWeOverrides.h (`#undef` + `#define` of every
  dotenv-injected value and every `--define` item, one entry per name, a `--define` winning over an
  injected value). A `--define` or an injected value wins over any Config.h line, bare or inside
  `#ifndef`, without a redefinition warning. Config.h no longer needs `#include <XeWeBuildInfo.h>`;
  one left in place is harmless.
- `#define NAME INJECTED_FROM_DOTENV` in Config.h takes NAME from the environment, else the dotenv
  file (`xewe build --env FILE`; also the builds of flash, run and test). A number is written bare,
  anything else as a C string. A missing value is exit 2 naming the Config.h line. The log and
  meta.json name the keys only; the release card shows `NAME=(dotenv)`.
- `xewe modules generate` adds a core block when the core ships a Config.h, keeps the section
  markers, and copies first-boot values as commented-out `// #define` lines.
- `xewe release` refuses a Config.h with an active INJECTED_FROM_DOTENV line.

BREAKING

- PROJECT_NAME is no longer generated. A sketch that reads it must switch to the device name.
- `--define` values are in XeWeOverrides.h, not XeWeBuildInfo.h. Code built by xewe sees them in
  every translation unit; code that read them only through `#include <XeWeBuildInfo.h>` outside a
  xewe build no longer finds them there.
- Dotenv keys renamed to the define names: XEWE_DEVICE_NAME -> XEWE_CORE_DEVICE_NAME,
  XEWE_WIFI_PASSWORD -> XEWE_WIFI_PSW, XEWE_TIMEZONE -> XEWE_TIME_TZ_GMT_STR (XEWE_WIFI_SSID
  unchanged). The old names are not read.

INSTALL

- Projects: `[tools] ref = "3.1.1"` in xewe.toml, then `./setup.sh`.
- Workflow callers: `uses: xewe-labs/xewe-os-tools/.github/workflows/<workflow>.yml@3.1.1`.

TESTING

What was tested, on which tree and with which result: release_card.md, generated by
scripts/release.sh --prepare 3.1.1 and attached to this release.
